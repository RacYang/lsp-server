# 根因修复缺陷

## When to use

当用户报告 bug、测试失败、线上异常或行为与契约不一致时使用。

## Inputs

- 复现步骤或失败日志。
- 期望行为与实际行为。
- 受影响的包、协议或文档。
- 初始根因假设、被破坏的不变量与责任边界。

## Steps

1. 先复现或定位最小失败面，不直接猜测修改。
2. 写出因果链：触发条件、错误传播路径、被破坏的不变量、责任模块和用户可见影响。
3. 添加能失败的回归测试或夹具，断言根因或不变量，而不是只断言表面错误消失。
4. 在拥有根因的模块或契约边界修复；拒绝吞错、任意默认值、扩大重试、sleep 或只服务单个现象的特殊分支。
5. 回归同一测试并扩展到相关 verify 目标。
6. 若只能临时缓解，必须说明风险、回收条件和后续根因修复入口，不把缓解当最终修复。

## Verify

- 运行新增或失败的目标测试。
- 确认测试能证明根因或不变量已经恢复。
- 根据影响面运行 `make verify-fast` 或 `make verify`。
- 最终说明中交代根因、修复点、回归证据与剩余风险。
