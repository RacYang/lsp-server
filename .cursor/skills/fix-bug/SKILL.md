# 修复缺陷

## When to use

当用户报告 bug、测试失败、线上异常或行为与契约不一致时使用。

## Inputs

- 复现步骤或失败日志。
- 期望行为与实际行为。
- 受影响的包、协议或文档。

## Steps

1. 先复现或定位最小失败面，不直接猜测修改。
2. 添加能失败的回归测试或夹具。
3. 修改最小实现，避免顺手重构无关模块。
4. 回归同一测试并扩展到相关 verify 目标。

## Verify

- 运行新增或失败的目标测试。
- 根据影响面运行 `make verify-fast` 或 `make verify`。
