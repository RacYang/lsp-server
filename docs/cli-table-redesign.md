# lsp-cli 纯中文 TUI 前端设计

本文是 `lsp-cli` 前端的唯一设计源。范围覆盖大厅、房间预备、牌桌、抢答、结算、浮窗和网络恢复。目标不是在旧命令行菜单上继续补 UI，而是把玩家端重建为一个全屏、纯中文、四向对称的终端麻将客户端。

本设计遵循 ADR-0047：不保留 emoji / unicode / ascii 主题切换，不保留三档 Tier，不保留 80x24 兼容路径。

## 1. 设计结论

| 维度 | 决策 |
| --- | --- |
| 产品形态 | 中文终端麻将客户端，不是协议调试器 |
| 视觉语言 | 汉字牌面 + Unicode 框线 + 少量语义色 |
| 主布局 | 框即牌桌，自己永远在南，下家西，对家北，上家东 |
| 最小尺寸 | `100x30`，低于此尺寸不进入牌桌 |
| 推荐尺寸 | `140x40` |
| 输入原则 | 枚举项用方向键选择；只有昵称和房间码允许文本输入 |
| 信息原则 | 玩家看到玩法语言，不看到 `rule_id`、`page_token`、`req_id` |
| 代码原则 | 单一路径渲染，不按主题分支，不靠日志文本反推状态 |

## 2. 审查结论

旧设计文档存在四类问题，必须一次性清掉：

1. **设计源冲突**：旧设计包仍描述 Unicode Mahjong Tiles、ASCII 降级、三档尺寸和侧栏；ADR-0047 已经要求纯中文、两档密度和单一路径。
2. **大厅形态冲突**：用户文档还写传统数字菜单，但代码已有 `LobbyScene` 全屏大厅。文档必须服从全屏 TUI。
3. **布局实现偏差**：渲染层曾经按布局计算紧凑间距，但实际画手牌时硬编码 3 列步长；东西两侧牌背区域高度与绘制步长不一致，标准尺寸会丢牌。
4. **玩家说明过期**：README 和玩法说明仍写 `unicode / ascii` 牌面主题、`64x20` 最小尺寸和菜单切换主题，这些都已被 ADR-0047 删除。

## 3. 页面骨架

所有场景共用同一个页面骨架：

```text
行 0        标题栏：产品名 / 当前场景 / 昵称 / 网络状态
行 1..H-3   内容区：大厅、牌桌、结算或浮窗
行 H-2      Toast：只显示瞬态错误或确认反馈
行 H-1      键位栏：只显示当前阶段可用动作
```

固定区必须预留空间，任何浮窗和牌桌不得覆盖标题栏、Toast 和键位栏。UI/UX Pro Max 的布局规则要求固定元素之间保留明确边界，避免固定层互相遮挡；本 TUI 用固定行位实现该约束。

## 4. 视觉系统

### 4.1 字符

- 牌面：中文牌名。
- 牌背：`牌`。
- 框线：单线 `┌ ┐ └ ┘ ─ │`；结算弹窗专用双线 `╔ ╗ ╚ ╝ ═ ║`。
- 进度条：`█` / `▓` / `░`。
- 玩家状态：`●` 在线、`○` 离线、`✓` 已准备、`胡` 已胡、`机` 机器人、`空` 空座。

### 4.2 颜色

颜色只表达状态，不做装饰：

| 语义 | 用途 |
| --- | --- |
| Default | 正常文本 |
| Emphasis | 反转视频，焦点、选中、当前玩家 |
| Dim | 次要信息、历史、pending |
| Danger | 离线、断连、错误 |
| Success | 在线、准备、成功 |
| Warning | 倒计时低于 5 秒、换三张标记 |

### 4.3 牌面

南家手牌使用两行竖排字：

```text
一 二 三 四 五 六 七 八 九 一 二 三 四
万 万 万 万 万 万 万 万 万 筒 筒 筒 筒
```

每张牌占 `2x2` cell。宽松布局步长为 3，紧凑布局步长为 2。布局必须按 14 张手牌计算，保证摸牌后第 14 张可见。

他家手牌只显示牌背。北家横排，西家和东家竖排贴边；标准尺寸下东西牌背不加行间距，确保 13 张全部可见。

## 5. 大厅

大厅是全屏 TUI，不再是 `stdin/stdout` 数字问答。

```text
lsp · 大厅 · racoo                                      ● 23ms

        ┌ 快速开始 ┐   ┌ 创建房间 ┐   ┌ 加入房间码 ┐   ┌ 公开房间 ┐
        │ 自动补齐 │   │ 选择玩法 │   │ 好友邀请   │   │ 等候房   │
        │ Enter    │   │ Enter    │   │ Enter      │   │ Enter    │

  公开房间
    Alice 的局        四川血战到底（换三张）    2/4    等待中
    Bob 的局          四川血战到底（标准）      1/4    等待中

←→/↑↓ 选择    Enter 确认    ? 帮助    q 退出
```

### 5.1 创建房间

创建房间是三步向导：

1. 选择玩法：展示 `display_name`、`short_desc`、玩家可读特性标签和局数，不展示 `rule_id`。
2. 选择公开性：`公开房间` / `私密房间`。
3. 确认房间名：默认 `玩法名 · 昵称`，玩家按 `Enter` 接受。

### 5.2 公开房间

公开房列表只展示房间名、玩法名、人数和玩家可读状态。分页只显示 `<` / `>` 和页码，不能显示 `page_token`。

### 5.3 加入房间码

房间码是大厅里唯一的业务文本输入。输入前显示格式提示，错误只进入 Toast，不破坏页面布局。

## 6. 牌桌

牌桌框就是麻将桌面。框内按“手牌 → 牌河 → 中心”的顺序围合。

```text
             对家：bob ● 分：+1200
    ┌──────────────────────────────────────────────────────────────┐
    │              牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌          │
    │  二万 三筒 七条 九万 一筒 四条                               │
    │                                                              │
alice ●  三万                                            七条  carl ●
         四筒                                            八万
         九条              ┌──────────────────┐          二筒
                           │    该你出牌      │
                           │       12s        │
                           └──────────────────┘
    │                                                              │
    │  九筒 七条 五万 三筒 二万 一筒                               │
    │              一 二 三 四 五 六 七 八 九 一 二 三 四           │
    │              万 万 万 万 万 万 万 万 万 筒 筒 筒 筒           │
    └──────────────────────────────────────────────────────────────┘
             你：racoo ● 分：+2400  剩36张
```

### 6.1 尺寸

| 终端 | 布局 |
| --- | --- |
| `<100x30` | 显示“窗口太小，请调大终端”，不进入牌桌 |
| `100x30..119x35` | 紧凑：横向牌间距 0，东西牌背紧密竖排 |
| `>=120x36` | 宽松：横向牌间距 1，中央信息区和牌河获得更多宽度 |

不再支持 64x20 或 80x24。不要为了小尺寸压缩语义信息；小尺寸直接拒绝。

### 6.2 中央区域

中央只显示当前阶段最重要的一件事：

- 等待：`等待玩家就位`
- 换三张：`选择三张同花色`
- 定缺：`请选择定缺`
- 自己行动：`该你出牌`
- 他人行动：`等待 alice`
- 抢答：由抢答弹窗接管
- 结算：`本局结束`

倒计时独占第二行。低于 5 秒使用 Warning。

### 6.3 桌外信息

玩家信息紧贴牌桌框外，不占用框内空间：

- 北：对家昵称、在线状态、分数。
- 南：自己昵称、在线状态、分数、剩牌。
- 西 / 东：昵称和状态，空间不足时截断，不挤压牌桌。

## 7. 房间预备

已进入房间但未开局时，仍使用同一张牌桌框。中央弹窗显示四座座位：

```text
┌ 座位 ───────────────────────────┐
│              ✓ 北 bob           │
│        ● 西 alice    空 东 空座  │
│              ✓ 南 racoo         │
└─────────────────────────────────┘
```

私密房在弹窗底部显示房间码。补机器人和准备状态必须来自服务端座位事实，不由前端猜测。

## 8. 阶段交互

| 阶段 | 输入 |
| --- | --- |
| 房间预备 | `b` 补 1 个机器人，`B` 补满，`q` 返回，`?` 帮助 |
| 换三张 | `←→` 移动，`Space` 标记，`Enter` 提交 |
| 定缺 | `m` 缺万，`p` 缺筒，`s` 缺条 |
| 出牌 | `←→` 选牌，`Enter` 出牌 |
| 抢答 | `←→` 选择，`Enter` 确认，或 `h/g/p/n` 直达 |
| 结算 | `r` 再开一桌，`l` 离桌，`Enter` 停留 |

键位栏只显示当前阶段可用动作，不能把全局帮助全部塞进去。

## 9. 浮窗

同一时间最多一个叠加层。

| 浮窗 | 触发 | 行为 |
| --- | --- | --- |
| 菜单 | `Esc` | 继续 / 返回大厅 |
| 房间信息 | `i` | 只读，`Enter` 或 `Esc` 关闭 |
| 玩家详情 | `Tab` | 只读，`Enter` / `Esc` / `Tab` 关闭 |
| 帮助 | `?` | 按当前场景裁剪 |
| 抢答 | 服务端候选动作 | 阻止其他输入，只接受抢答相关键 |
| 结算 | `SettlementNotify` | 双线弹窗，逐行揭晓 |

## 10. 网络恢复

网络状态是叠加层，不是独立场景：

- 短暂断线：标题栏显示 `○ 重连中 Ns`。
- 长时断线：牌桌中央显示网络浮窗，不清空原牌局。
- 恢复后：根据服务端快照回到大厅、预备、牌桌或结算。
- 离线超过阈值：浮窗允许 `Enter` 返回大厅。

## 11. 数据边界

| UI 信息 | 来源 |
| --- | --- |
| 玩法 | `RuleMeta.display_name` / `short_desc` / `enabled_features` |
| 公开房 | `ListRoomsResponse.rooms` |
| 座位 | `SeatInfo` 和 `SnapshotNotify.seats` |
| 手牌 | `InitialDealNotify` / `DrawTileNotify` / `SnapshotNotify.your_hand_tiles` |
| 牌河 | `ActionNotify` / `SnapshotNotify.discards_by_seat` |
| 副露 | `SnapshotNotify.meld_infos_by_seat` |
| 当前动作 | `phase` / `acting_seats` / `available_actions` / `waiting_action` |
| 抢答 | `claim_candidates` / `available_actions` |
| 倒计时 | `deadline_unix_ms` |
| 剩牌 | `wall_remaining` |
| 结算 | `SettlementNotify` |
| 网络 | 连接状态 / `RouteRedirectNotify` |

缺字段时隐藏对应 UI。客户端估算只能作为桌外辅助文案，且不能写回协议事实。

## 12. 验收清单

- [ ] 大厅、预备、牌桌、结算都在同一个全屏 TUI 内完成。
- [ ] 创建房间和公开房列表不出现 `rule_id`、`page_token`、`req_id`。
- [ ] 牌桌低于 `100x30` 时拒绝进入。
- [ ] `100x30` 标准尺寸下北、西、东三家 13 张牌背全部可见。
- [ ] 南家 14 张手牌完整可见。
- [ ] 键位栏只显示当前阶段动作。
- [ ] 断线恢复后根据快照回到正确场景。
- [ ] README、玩法说明和 ADR-0047 不再互相冲突。
- [ ] `go test ./cmd/cli/...` 通过。
