# lsp-cli TUI 前端设计包

本文是 `lsp-cli` 牌桌 TUI 的开工前设计包。它只描述需求、UI/UE、前端技术架构、数据来源、降级策略和验收标准；不包含代码实现计划，也不补后端契约。

## 1. 需求理解

玩家进入牌局后，第一眼看到的必须是一张稳定、居中的俯视麻将桌，而不是管理后台式的信息面板。桌内只出现真实牌桌上会存在的对象；解释、建议、历史、网络等辅助信息退到桌外区域。

玩家不看说明也要能判断：

- 我坐在哪里。
- 当前轮到谁。
- 刚打了哪张。
- 我现在可以做什么。
- 我的手牌、牌河、副露分别在哪里。
- 牌局处于等待、换三张、定缺、出牌、抢答、结算还是断线状态。

## 2. 玩家任务流

```text
启动客户端
  -> 登录或静默续登
  -> 进入大厅
  -> 快速开始 / 创建房间 / 输入房间码
  -> 进入牌桌
  -> 等待玩家
  -> 换三张
  -> 定缺
  -> 摸打循环
  -> 碰 / 杠 / 胡 / 过
  -> 结算
  -> 再来一局或离桌
```

每一步都要有一个明确的主焦点。牌桌阶段的主焦点永远先落在中心牌桌，其次才是桌外辅助。

## 3. 信息边界

### 桌内允许

- 四家手牌或牌背。
- 四家牌河。
- 四家副露。
- 最近一打。
- 桌心剩牌、计时、庄位。
- 方位与短昵称。
- 当前焦点的最小提示。

### 桌外允许

- 房间、规则、网络、RTT。
- 玩家详情。
- 最近事件。
- 听牌建议。
- 危险提示。
- 战绩趋势。
- 快捷键帮助。

### 禁止

- 桌内出现长句教学文案。
- 桌内出现大段历史日志。
- 用侧栏挤偏中心牌桌。
- 用 Unicode 牌图标的显示宽度承担布局。

## 4. UI/UE 原则

1. **中心牌桌优先**：正中牌桌居中、稳定、优先级最高。侧栏不足时隐藏，不压缩桌内核心对象。
2. **真实俯视映射**：自己永远在南边；下家在左；对家在北；上家在右。牌河从各自面前向桌心推进。
3. **桌内少字**：桌内用位置、牌、方向和少量图标表达牌局。长解释放桌外。
4. **一屏一焦点**：同一时刻只强调一个当前动作区域，例如自己的手牌、抢答弹层或结算结果。
5. **黑白可读**：不依赖颜色表达核心语义，继续使用黑白、反白、粗细、密度块。
6. **图标可降级**：Unicode Mahjong Tiles 是牌面，不是布局基础；宽度异常时回退到 CJK 或 ASCII。
7. **底栏只放当前动作**：底部不堆所有快捷键，只展示当前阶段最相关的键。

## 5. 尺寸档位

终端 cell 视觉近似为 1:2，所以视觉正方形牌桌在实现上满足 `TableFrame.Width == TableFrame.Height * 2`。

| 档位 | 终端 | 中心牌桌 | 桌外信息 |
| --- | ---: | ---: | --- |
| Standard | `100x30` | `52x26` | 隐藏侧栏，只保留顶栏和底栏 |

| Full | `140x40` | `72x36` | 左右侧栏都显示 |

## 6. 状态稿

### 等待开局

- 焦点：中心牌桌空位和四家就位状态。
- 桌内：四个方位、已入座玩家短名、空座。
- 桌外：房间号、规则、人数、是否机器人补位。
- 底栏：`Enter 等待真人    b 补 1 个机器人    B 补满    Esc 菜单`。
- 失败反馈：补机器人失败只在底栏或右侧短暂提示，不弹大窗。

### 换三张

- 焦点：自己的手牌和已标记三张。
- 桌内：自己的手牌、被标记牌、其它玩家等待态。
- 桌外：右侧显示 `已选 N/3` 和规则短提示。
- 底栏：`←→ 选牌    Space 标记/取消    Enter 提交    Esc 取消`。
- 超时反馈：倒计时进入最后 3 秒时，底栏反白。

### 定缺

- 焦点：底栏动作和自己的缺门选择。
- 桌内：自己的手牌仍在南边，缺门选择不遮挡手牌。
- 桌外：右侧显示 `m 万 / p 筒 / s 条` 的中文解释。
- 底栏：`m 缺万    p 缺筒    s 缺条    Esc 菜单`。
- 失败反馈：提交失败后右侧显示原因，底栏保留选择键。

### 自己出牌

- 焦点：自己的手牌光标。
- 桌内：自己的手牌、牌河、桌心剩牌/计时。
- 桌外：右侧可显示听牌建议，但必须标注为辅助。
- 底栏：`←→ 选牌    Enter 出牌    i 房间    Esc 菜单`。
- 提交中：被提交牌变为低亮，避免重复操作。

### 他人出牌

- 焦点：当前行动座和桌心倒计时。
- 桌内：当前行动座边缘或短名反白；桌心显示剩牌/计时。
- 桌外：最近事件显示 `等待 alice 出牌`。
- 底栏：`Tab 玩家    i 房间    ? 帮助    Esc 菜单`。
- 超时反馈：不抢占屏幕，等待服务端推进。

### 碰 / 杠 / 胡抢答

- 焦点：抢答弹层。
- 桌内：最近一打保持在桌心附近，抢答弹层小而明确。
- 桌外：右侧暂停普通辅助，显示抢答倒计时和动作解释。
- 底栏：`←→ 切换    Enter 确认    h 胡    g 杠    p 碰    n 过`。
- 超时反馈：倒计时归零自动过，弹层关闭。

### 结算

- 焦点：结算弹层。
- 桌内：牌桌作为背景保留，不清屏。
- 弹层：显示胜负、番种、每家得失、再来一局/离桌。
- 底栏：`R 再来一局    L 离桌    Enter 停留`。
- 桌外：可显示本局摘要，但不替代结算弹层。

### 断线重连

- 焦点：仍保留牌桌，网络状态不应立即遮挡中心。
- 顶栏：显示 `○ 重连中 Ns`。
- 超过阈值：弹出小型中央浮层 `网络长时间无法恢复`。
- 底栏：`Enter 返回大厅    Esc 菜单`。
- 恢复后：顶栏恢复 `● 在线`，牌桌状态通过快照同步。

## 7. 前端技术架构

目标数据流：

```text
RoomView
  -> InteractionModel
  -> TableScene
  -> LayoutModel
  -> RenderLayers
  -> tcell.Screen
```

### InteractionModel

职责：把协议事实翻译成 UI 阶段、可行动作、当前焦点。

输入来自现有 `RoomView`：

- `Phase`
- `WaitingAction`
- `RoundPhase`
- `ActingSeat`
- `ActingSeats`
- `AvailableActions`
- `ClaimCandidates`
- `LastSettlement`

输出：

- 当前 UI 阶段。
- 当前行动座。
- 当前可操作键。
- 当前焦点对象。
- 抢答或结算弹层模型。

### TableScene

职责：描述真实牌桌对象，不关心屏幕坐标。

建议字段：

- `Seats[4]`
- `SelfSeat`
- `DealerSeat`
- `Hands`
- `HandCounts`
- `Discards`
- `Melds`
- `LastAction`
- `Center`
- `Timer`
- `Overlays`

### LayoutModel

职责：根据终端尺寸产出坐标。

区域：

- `TableFrame`
- `TableInner`
- `TopModeline`
- `BottomModeline`
- `LeftRail`
- `RightRail`
- `DialogAnchor`

约束：

- `TableFrame.Width == TableFrame.Height * 2`。
- `TableFrame` 居中。
- 侧栏按宽度折叠。
- 桌内牌对象不因侧栏出现而改变语义位置。

### RenderLayers

渲染层顺序：

1. `table`: 中心正方形牌桌。
2. `sideRails`: 桌外信息。
3. `modeline`: 顶部上下文和底部动作。
4. `dialog`: 抢答、结算、离线等临时层。
5. `network`: 网络状态提示，优先 modeline，必要时浮层。

### tile/icon

职责：

- Unicode Mahjong Tiles。
- CJK 中文牌。
- ASCII 牌。
- 宽度探测与回退。
- 牌背统一表达。

规则：

- 不以 Unicode 牌图标宽度计算布局。
- 图标宽度异常时，仅替换牌面渲染，不改变区域坐标。

## 8. 数据契约盘点

### 当前可用事实

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 自己座位 | `JoinRoomResponse.seat_index` / `SnapshotNotify` | 固定南边视角 |
| 庄家 | `StartGameNotify.dealer_seat` | 桌心和玩家标记 |
| 自己手牌 | `InitialDealNotify.tiles` / `DrawTileNotify.tile` / `SnapshotNotify.your_hand_tiles` | 南家手牌 |
| 他家手牌数 | `SeatInfo.hand_count` + 本地增减 | 牌背数量 |
| 弃牌 | `ActionNotify(discard)` / `SnapshotNotify.discards_by_seat` | 四家牌河 |
| 副露文本 | `ActionNotify(pong/gang)` / `SnapshotNotify.melds_by_seat` | 副露显示 |
| 当前行动 | `phase` / `acting_seats` / `waiting_action` | 焦点和底栏 |
| 抢答窗口 | `claim_candidates` / `available_actions` / `pending_tile` | 抢答弹层 |
| 结算 | `SettlementNotify` | 结算弹层 |
| 网络状态 | `RoomView.Connected` / `Reconnecting` / `RTTms` | 顶栏状态 |

### 当前缺失或不够稳定

- 结构化副露。
- 结构化最后动作。
- 权威剩牌数。
- 服务端行动 deadline。
- 玩家在线/断线/托管细分状态。
- 实时积分。
- 权威局号。
- 权威听牌/可胡提示。

## 9. 降级策略

### 尺寸降级

- `140x40`: 两侧信息栏完整显示。
- `120x36`: 右侧关键辅助显示，左侧隐藏或压缩。
- `100x30`: 只显示中心牌桌、顶栏、底栏。
- 低于 `100x30`: 拒绝进入牌桌，提示放大终端。

### 牌面降级

顺序：

1. Unicode Mahjong Tiles。
2. CJK 中文牌。
3. ASCII 牌。

触发条件：

- 字体不支持 Mahjong Tiles。
- `visualWidth` 与预期不符。
- 用户主动选择 ASCII。

### 信息降级

- 服务端事实缺失：不显示或显示未知。
- 客户端估算：只放桌外，并标注辅助性质。
- 网络异常：先用 modeline，不立即遮挡桌面。

## 10. Fixture 与 Golden 建议

### Fixture

每个 fixture 都应固定：

- `RoomView`
- `InteractionModel`
- 终端尺寸
- 牌面主题
- 当前时间
- 光标状态

### Golden 覆盖

尺寸：

- `100x30`
- `120x36`
- `140x40`

状态：

- 等待开局。
- 换三张。
- 定缺。
- 自己出牌。
- 他人出牌。
- 抢答。
- 结算。
- 断线重连。

牌面：

- Unicode。
- CJK。
- ASCII。

验收：

- 牌桌边界不散架。
- 四家方位稳定。
- 桌内没有长句。
- 底栏只显示当前阶段动作。
- 侧栏隐藏时中心牌桌仍可玩。

## 11. 交接给前端实现 agent

前端实现 agent 应从以下顺序开始：

1. 建立 `TableScene` 与 `LayoutModel` 纯函数。
2. 先实现 `drawSquareTable`，不接侧栏。
3. 加三档尺寸 golden。
4. 加 `drawModeline`。
5. 加 `drawSideRails`。
6. 重做抢答与结算弹层。
7. 完成 Unicode/CJK/ASCII fallback。
8. 最后再做听牌、危险、战绩等桌外增强。

在后端契约补齐前，前端不得把估算信息放进桌内。
