# lsp-cli 文字牌局前端设计

本文是 `lsp-cli` 玩家前端的唯一设计源。`lsp-cli` 是 `lsp-server` 配套的正式终端 TUI 客户端，同时也是纯终端产品体验实验；它面向玩家，开发者调试身份必须退到次级。

设计主题为 **文字牌局**：不是在终端里画一张麻将桌，而是用文字构成一局麻将。牌、位置、动作、等待、结算都应像同一套文字系统的一部分。

## 1. 产品定位

`lsp-cli` 的默认体验是“打开就能玩”。玩家可以是开发者，但进入客户端后首先是玩家：

- 玩家不看协议字段，不理解服务端拓扑，也不关心 frame dump。
- 玩家主流程只出现游戏语言：等人、开局、换三张、定缺、出牌、碰、杠、胡、过、结算。
- 调试能力可以存在，但必须通过显式调试路径进入，不得污染大厅、牌局和结算。

后续会有独立前后端分离项目；本设计不考虑 Web、桌面 GUI 或移动端。

## 2. 设计语言

### 文字即物

文字不是低配图形，也不是说明文字。文字本身就是界面对象：

- `一万`、`九筒`、`东风` 是牌，不需要再包成复杂牌框。
- `碰`、`杠`、`胡`、`过` 是可行动作，不需要解释为命令。
- `你`、`下家`、`对家`、`上家` 是空间关系，不需要用协议座位号表达。
- `剩36张`、`庄`、`听`、`已胡` 是局面事实，不需要调试日志补充。

### 留白成景

终端空间要有呼吸感。不要把每个角落都塞满，也不要用卡片和边框证明“这是 UI”。留白用于表达：

- 当前行动的重量。
- 自己手牌和牌河的关系。
- 等待、思考、抢答、结算的节奏。

### 少框线、少面板、少工程词

框线只用于关键边界：主牌局、模态决策、结算揭晓。普通信息不放进卡片。大厅入口、状态提示、键位提示优先用文字位置和反白表达。

禁止玩家主流程出现：

- `rule_id`、`req_id`、`page_token`、`phase`、`snapshot`、`cursor`。
- `cmd/cli`、`/tmp`、frame dump、内部 gateway、LocalGateway。
- 以调试为目的的协议字段、日志片段、错误码原文。

## 3. 信息层级

每一帧按以下顺序决定视觉权重：

1. **当前行动**：轮到谁、要做什么、如何确认。
2. **自己手牌**：可选择、已标记、pending、不可打的状态。
3. **可响应动作**：碰、杠、胡、过、定缺、换三张。
4. **局面事实**：四家、牌河、副露、剩牌、庄位、分数、在线状态。
5. **辅助信息**：房间码、规则名、网络状态、帮助入口。

如果空间不足，优先保留 1~3；辅助信息隐藏或进入浮层。

## 4. 场景设计

### 启动与登录

启动只做一件事：把玩家带到大厅。已有会话时静默续登；需要昵称时只问昵称。错误用玩家语言表达，例如“连接失败，请检查服务器地址”，不显示底层错误栈。

### 大厅

大厅是进入牌局的门厅，不是功能面板。主视觉只保留四个入口：

```text
快速开始        创建房间        加入房间        公开房
```

选中项反白或加强，不使用厚重卡片。公开房列表作为次级信息出现在下方，只显示房名、玩法、人数、状态。

### 创建房间

创建房间是三段文字选择：

1. 选玩法：展示玩家可读名和一句简介。
2. 选公开性：公开 / 私密。
3. 确认房名：默认即可，只有主动修改时进入文本输入。

不要要求玩家输入规则 ID。

### 加入房间

加入房间是唯一保留业务文本输入的入口。输入框不做复杂装饰，只显示“输入房间码”。错误进入一行提示，不改变页面结构。

### 房间预备

房间预备表达“人是否齐、是否能开局”。座位状态用文字关系表达：

```text
        对家  bob  已准备

下家  alice  在线          上家  空座

        你    racoo 已准备
```

私密房码是可分享事实，持续显示到开局前。补机器人是玩家动作，但不能喧宾夺主。

### 牌局

牌局第一焦点是当前行动，不是桌面拟物。默认结构：

```text
          对家 bob

    二万 三筒 七条

下家 alice                 上家 carl

          轮到你：选择一张牌打出

一万 二万 三万 五筒 六筒 七筒 九条
你 racoo      剩36张      庄
```

牌河和他家信息围绕当前行动摆放，但不能挤压行动句和自己手牌。真实牌桌方位可以保留，但不优先追求拟物。

### 换三张与定缺

换三张要清楚表达“已选几张”和“同花色限制”：

```text
换三张：已选 2/3　Space 标记　Enter 确认
```

定缺要表达一次性决定：

```text
定缺：m 缺万　p 缺筒　s 缺条　选定后不可更改
```

### 抢答

抢答是模态决策。它可以使用边框，因为它会暂时接管输入。内容按玩家语言组织：

```text
alice 打出 七筒

碰        胡        过

还剩 4 秒
```

可选项反白，倒计时低于 5 秒用 Warning，但不能只靠颜色表达。

### 结算

结算是揭晓，不是账单表格。先给结论，再给分数：

```text
本局结束：你胡了

你      +24
alice   -8
bob     -8
carl    -8

r 再开一桌　l 离桌　Enter 停留
```

多赢家、罚分、荒局必须分段展示，不能压成一行日志。

### 断线

断线不清空当前牌局。短断线在标题或角落提示；长断线用一段居中文字说明：

```text
连接断开，正在重连
已等待 12 秒
```

只有长时间无法恢复时，才提供返回大厅动作。

## 5. 交互规范

底栏使用动作句，不使用命令表。动作句格式：

```text
状态：主要按键　次要按键
```

示例：

- `轮到你：←→ 选牌　Enter 打出`
- `换三张：已选 2/3　Space 标记　Enter 确认`
- `等待 bob：? 查看帮助`
- `本局结束：r 再开一桌　l 离桌　Enter 停留`

全局帮助只在 `?` 浮层里展示。底栏永远只服务当前状态。

## 6. 视觉约束

- 主色为终端默认色；反白表达焦点。
- Danger / Warning / Success 只表达状态，不做装饰。
- 任何状态都不能只靠颜色表达，必须有文字或符号。
- CJK 字符宽度按 `uniseg` 计算；所有固定布局必须用 visual width。
- 固定区域不能重叠：标题、内容、Toast、动作句各占独立行。

## 7. 调试边界

调试信息退出玩家空间：

- frame dump 写入调试文件，不在玩家 UI 出现。
- `/tmp` 只作为测试和 dump 目录，不作为启动或玩家概念。
- 协议字段只存在于代码、日志和调试工具，不进入玩家文案。
- Debug 模式可以新增独立浮层或启动参数，但默认关闭。

## 8. 暂不追求

本设计暂不追求：

- 高拟真的麻将桌。
- Web 前端、桌面 GUI、移动端。
- 复杂动效和动画系统。
- 聊天、观战、回放。
- 把调试工具做进玩家主界面。

这些可以作为后续独立设计，不在文字牌局 v1 中混入。

## 9. 验收标准

- 玩家第一眼能看出“现在该谁做什么”。
- 玩家不需要理解协议、服务端、路径或调试概念。
- 大厅、牌局、结算像同一个文字系统，而不是卡片、表格、日志拼接。
- 当前行动提示使用动作句。
- 旧文档只能引用本文，不再作为设计决策来源。
