# ADR-0043 根因优先的问题处理策略

## 状态

已采纳。

## 背景

Agent 处理缺陷、测试失败或线上异常时，容易为了让当前现象消失而添加局部 guard、重试、默认值、吞错或特殊分支。这类补丁式修复短期能让测试变绿，却会把真实原因转移到更隐蔽的位置，增加后续排查成本。

本仓库已经通过 ADR-0042 建立 Agent 治理体系，但 `fix-bug` 流程仍偏向“复现、补测试、最小改动、回归”，没有明确要求先解释因果链、定位责任边界和拒绝症状掩盖。

## 决策

1. 查问题和修问题必须先形成可解释的因果链：触发条件、错误传播路径、被破坏的不变量、责任模块与用户可见影响。
2. 修复必须落在拥有根因的模块或契约边界上，而不是只在调用方、展示层或测试中屏蔽症状。
3. 回归测试必须钉住根因或被破坏的不变量；只断言“当前错误不再出现”的测试不足以证明修复成立。
4. 禁止把未知状态静默降级为默认值、吞掉错误、扩大重试、增加任意 sleep 或添加仅服务单个现象的特殊分支，除非 ADR 或稳定契约明确要求这种兼容行为。
5. 如果暂时无法根因修复，必须把临时缓解标记为未完成的风险项，说明回收条件、验证路径和后续根因修复入口；不得把缓解伪装为最终修复。
6. Agent 在最终说明中应交代根因、修复点、回归证据与剩余风险；如果证据不足，应明确说明没有完成根因修复。

## 后果

- `fix-bug` skill 必须把根因分析放在改代码之前。
- 覆盖矩阵需要把缺陷修复从一般 evolve 任务提升为根因修复路径。
- 机器校验只能验证流程资产形态，不能替代人类对根因质量的评审；除非某类补丁反模式可稳定检测，才新增 narrow constraint rule。
