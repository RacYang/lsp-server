# ADR-0047：CLI 纯中文 TUI 重构

## 状态

已采纳。取代 ADR-0038 的"三主题牌面"与"黑白美学"决策。

## 背景

ADR-0038 定义了 CLI 牌桌的三主题牌面（emoji、unicode、ascii）与黑白视觉语言。实际运行暴露三个问题：

1. **宽度计算不确定**：emoji 在不同终端上宽度不一（有的终端 emoji 占 1 列、有的占 2 列），导致牌桌 layout 计算偏离。
2. **框线风格混乱**：混用 ASCII（`+` `-` `|`）与 Unicode Box Drawing（`┌` `─` `│`），golden 文件两套并存。
3. **设计语言不统一**：牌面主题切换、组件增补式开发、Tier 密度系统过度工程化，维护负担重。

本 ADR 做一次彻底的"涅槃式"重构：去掉所有历史包袱，用纯中文宽字符重新设计整个 CLI 前端。

## 决策

### 1. 设计哲学

参考 Steam《文字游戏》的核心理念：

| 原则 | 描述 |
|------|------|
| 汉字即 UI | 牌名、标签、按钮、状态——全部用中文表达，不依赖图标或 emoji |
| 留白即语言 | 空间分隔表达信息层次，不做密集排列 |
| 单色为主 | 仅在告警状态使用颜色（红/绿/黄），其余用默认前景、反转视频、灰度 |
| 逐字节奏 | 每个 CJK 字符占 2 列，确定性宽度计算 |

### 2. 牌面符号

**手牌（南家）**：竖排显示。每张牌 2 行×2 列，数字在上花色在下。

```text
一 二 三 四 五 六 七 八 九 一 二 三    ← 第一行：数字
万 万 万 万 万 万 万 万 万 筒 筒 筒    ← 第二行：花色
```

- 13 牌行宽：13×2 + 12×1 = 38 列
- 14 牌行宽：14×2 + 13×1 = 41 列
- 光标选中：反转视频覆盖 2×2 区域
- 已标记（换三张）：黄色前景
- 摸到的牌：反转视频 + 粗体

**手牌（北家）**：一横排牌背。

```text
牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌    ← 13 张牌背
```

**手牌（西/东家）**：一竖排牌背，紧贴边框内侧。

**牌河**：横排完整中文名，每张 2 字 4 列，间距 1 列。自动换行。

**字牌名称**：东风、南风、西风、北风、红中、发财、白板

**牌背符号**："牌"（U+724C）

### 3. 框线体系

统一使用 Unicode Box Drawing，彻底移除 ASCII 后备。

- 单线：`┌` `┐` `└` `┘` `─` `│` `├` `┤` `┬` `┴` `┼`
- 双线（仅结算弹窗）：`╔` `╗` `╚` `╝` `═` `║`
- 填充（进度条）：`█`（满） `▓`（半） `░`（空）

### 4. 颜色体系

5 种语义色，不引入装饰色。

| 语义 | tcell Color | 用途 |
|------|-------------|------|
| Default | 无覆盖 | 所有正常文本 |
| Emphasis | 反转视频 | 选中/焦点/当前玩家 |
| Dim | 灰色 | 次要信息、历史记录 |
| Danger | 红色 | 离线、断连、错误 |
| Success | 绿色 | 在线、已准备、成功 |
| Warning | 黄色 | 倒计时 < 5 秒、过期 |

### 5. 布局网格 —— 框即牌桌

**牌桌框 = 麻将桌面**。框内是俯视牌桌：四家手牌靠边，牌河在中间，中心留空。

```text
             对家：alice ● 1800分                      ← 框外上：北玩家
    ┌──────────────────────────────────────────┐
    │  牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌 牌  │  ← 北手牌（一横排·背向）
    │  一万 二条 三筒 四万 五条 六筒 七万 ... │  ← 北牌河
    │                                          │
alice│ 三万          ┌─────────┐       七条     │bob  ← 框外左右：西/东玩家
  ● │ 四筒          │ 轮到你了 │       八万     │○
    │               │ 请出牌   │               │
    │ 西牌河        │ 12s     │       东牌河    │
    │               └─────────┘               │
    │                                          │
    │  九筒 七条 五万 三筒 二万 一筒 四万 ... │  ← 南牌河
    │  一 二 三 四 五 六 七 八 九 一 二 三 四 │  ← 南手牌（一横排·正向竖排）
    │  万 万 万 万 万 万 万 万 万 筒 筒 筒 筒 │
    └──────────────────────────────────────────┘
             你：racoo ● 庄 2400分  剩36张           ← 框外下：南玩家+牌山计数
```

**四向对称结构（手→河→中心）**：

| 方位 | 手牌 | 牌河 | 玩家信息 |
|------|------|------|----------|
| 南 | 一横排·竖排正向 | 横排，手牌与中心之间 | 框外下 |
| 北 | 一横排·背向 | 横排，手牌与中心之间 | 框外上 |
| 西 | 一竖排·背向（贴左边框） | 竖排，墙与中心之间 | 框外左 |
| 东 | 一竖排·背向（贴右边框） | 竖排，墙与中心之间 | 框外右 |

**牌山**：不绘制牌山。框外右下显示"剩 N 张"。

**中央区域**：四家牌河围合的中心空白区域，显示阶段提示、倒计时、操作状态。这是牌桌的"呼吸空间"。

**页面骨架**（固定）：

```text
行 0：        标题栏（1行）
行 1 ~ H-3：  内容区（居中牌桌 + 上下玩家信息）
行 H-2：      Toast（1行，仅在有消息时渲染）
行 H-1：      键位栏（1行）
```

**尺寸约束**：最小 100×30，推荐 140×40。低于最小尺寸显示"窗口太小，请调大终端"。

**自适应等级**：仅 2 级（宽松/紧凑），去掉 ADR-0038 的三档 Tier 与滞回逻辑。

- 宽松：牌间距 1 列/行，所有牌正常间距
- 紧凑：牌间距 0，在窄屏时压缩

**玩家状态符号**：●在线 ○离线 ✓已准备 胡已胡 机机器人 空空座

### 6. 组件体系

| 组件 | 用途 |
|------|------|
| `DrawBox` | 带标题的边框（单线/双线） |
| `DrawDialog` | 居中模态框 |
| `DrawPanel` | 简单信息面板 |
| `DrawPlayerCard` | 单张玩家卡片（框外渲染） |
| `DrawTileRow` | 竖排手牌行，支持光标和标记 |
| `DrawTilePond` | 牌河网格，支持多行换行 |
| `DrawProgressBar` | 带标签进度条（`█▓░`） |
| `DrawToast` | 瞬态通知 |
| `DrawBandLine` | 左右对齐的横带（标题栏/键位栏） |

### 7. 交互规范

- 光标模式：`None`（禁止操作）、`Single`（出牌选择，左/右移动，Enter 确认）、`Multi3`（换三张，Space 标记/取消，凑 3 张 Enter 提交）
- 叠加层栈：最多同时一个（菜单 / 房间信息 / 玩家详情 / 帮助）
- 模态弹窗：鸣牌选择 / 结算揭晓（阻止其他输入）
- 键位绑定：`←→` 移动光标，`Enter` 确认，`Esc` 菜单/返回，`?` 帮助，`q` 退出，`i` 房间信息，`Tab` 玩家详情，`h` 胡，`g` 杠，`p` 碰，`n` 过
- 键位栏始终用中文提示，如"←→选择 Enter确认 Esc菜单 ?帮助"

### 8. 移除项

以下从代码库中完全移除：

- `TileTheme` 枚举及所有主题切换逻辑
- `tile_art.go`、`tile_art_test.go`（类型别名和主题解析器）
- Emoji 牌面映射表（`emojiTileGlyph` 等 34 个 case）
- ASCII 框线后备（`tcell.RuneULCorner` 回退路径）
- 三档 Tier 密度系统（`resolveTier`、`tierCanPromote`、`tableSizeForTier`）
- `TileGlyphCompact`、`TileGlyphTheme` 等主题相关类型
- 配置字段：`TileTheme`、`ClaimTimeoutMS`
- 旧 golden 文件（全部重新生成）
- `TILE-ART.md` 文档

## 后果

### 正面

- 宽度计算完全确定：每个中文字符 = 2 列，无平台/终端差异
- 代码量大幅减少：移除 3 种主题 × 每个渲染分支 = 大量分支代码
- 维护负担降低：单一渲染路径，新增功能无需考虑多主题兼容
- 视觉一致性：所有界面使用相同的中文字符和框线风格
- 符合中文使用习惯：竖排手牌、四向对称布局

### 负面

- 失去 emoji 牌面的"图形化"视觉（用户群可能偏好图形牌面）
- 牌面信息密度降低：每张竖排牌比横排多占 1 行
- 需至少 100 列终端（旧 80×24 终端不再支持）

### 过渡

- 不做渐进迁移，一次性 cut over
- 不保留 `LSP_CLI_LEGACY_THEME` 环境变量
- 新旧 golden 文件无兼容路径
