# ADR-0049 零债务重构策略

## 决策

- 所有修复/新增前必须先完成全系统梳理：找出职责所有者、调用链、当前状态与最优目标状态的 diff。
- 修复落点规则：根因在哪一层，修复就在哪一层；不在调用方、展示层或测试层掩盖根因。
- 判断补丁信号：修复后代码行数净增（删除 < 新增）且没有接口变化，大概率是补丁，需要重新审视。
- 临时缓解必须标注 `TODO(debt): <回收条件>` 且不得作为最终提交合入主干；无回收条件的 TODO 不允许存在。
- 重构范围无上限：宁可一次性把职责边界改清楚，也不接受"先小改、以后再说"。
- 本策略与 ADR-0043（根因优先修复）互补：ADR-0043 约束修 bug 流程，本文档约束所有代码变更的起点思维。

## 后果

- `fix-bug`、`scaffold-package`、所有重构任务开始前，agent 必须输出"职责所有者分析"和"目标状态描述"再动代码。
- 无法满足上述要求时，任务暂停并向用户说明阻塞原因，不得悄悄降级为补丁。
- 代码审查标准：任何新增的 guard/default 值/吞错，需要引用其所属的 ADR 或稳定契约，否则视为潜在补丁。
